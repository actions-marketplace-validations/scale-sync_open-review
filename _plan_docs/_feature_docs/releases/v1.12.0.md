# v1.12.0 — Rust SDK and repeatable distribution

## Three features

1. **Rust SDK.** Publish a crate with typed review/scan results and safe process or service boundary; no duplicate review algorithm.
2. **Binary distribution.** Build signed or checksummed Go binaries for supported platforms, with tested GitHub Release assets, install scripts, and a Homebrew path where ownership is available.
3. **Cross-SDK compatibility.** Run the same contract fixtures through Go, Node, Python, and Rust; validate version negotiation, cancellation, errors, and partial coverage across platforms.

## Implementation boundary

Keep `sdk/rust/` and release packaging separate from `review/internal/`. One release manifest ties SDK versions, contract version, binary hashes, and supported platforms together. Avoid a shared FFI layer unless a concrete platform limitation requires it.

## Release gate

Cargo package dry-run, artifact install tests, checksums, license/notice review, architecture matrix, and real registry retrieval after publication. Record any unsupported target and its failure mode in release notes.
