# v1.13.0 — provider profiles and installable CLI

## Added

1. **Named provider profiles.** Add `config provider list|use|remove|test` for OpenAI, Anthropic, Gemini, OpenRouter, local endpoints, and enterprise gateways. Preserve the current single-provider config as a readable migration format.
2. **Custom provider records.** Store protocol, base URL, auth-header, model aliases, and environment-variable references for each profile. Secrets stay in mode-0600 local state or environment variables and never appear in argv or normal output.
3. **Installable CLI channel.** Publish an npm wrapper that selects and verifies the matching checksummed platform binary. Keep the existing direct binary and install-script paths available for offline and enterprise use.

## Scope and proof

Provider profile tests must cover create, select, rotate, remove, migration from the current config, masked display, custom OpenAI-compatible and Anthropic protocols, local HTTP exceptions, and environment-variable references. A subprocess test must prove that secrets do not appear in argv, logs, or error messages. The npm package must resolve the correct target, verify its SHA-256 manifest entry, and fail closed on a mismatch. Registry publication is a release gate and requires verified package ownership and retrieval; local packaging alone is not publication proof.
