# v1.14.0 — review artifacts and session operations

## Added

1. **Session comments command.** Add `sessions comments` with severity, category, triage-state, and JSON filters so scripts can consume persisted findings without parsing terminal output.
2. **Stable review artifact.** Define a versioned artifact containing coverage, findings, triage, model identity, token/time usage, audit events, and partial-failure reasons. SDKs and CI can consume the same schema.
3. **Offline and loopback reporting.** Make self-contained HTML export and the loopback session viewer documented first-class workflows, with stable links, private-by-default output, and explicit source-content handling.

## Scope and proof

Artifact fixtures must round-trip complete, partial, failed, and triaged sessions while preserving finding IDs and coverage states. Filter tests must prove deterministic ordering and JSON/text parity. HTML exports must open without network access, escape source and finding text, and never embed credentials or prompts. Viewer tests must remain loopback-only and model-free. Schema compatibility must be checked by the Go, TypeScript, Python, and Rust SDKs before release.
