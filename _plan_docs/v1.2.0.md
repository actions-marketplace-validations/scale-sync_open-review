# v1.2.0 — explainable rules

## Three features

1. **Rule precedence.** Resolve explicit-run, repository, user, and built-in rules in a documented order per file.
2. **Language and path rules.** Built-in and custom path/glob rules cover supported languages and config files; include/exclude logic remains separate from prompt guidance.
3. **Rule diagnostics.** `rules check`, preview, and per-run background context show the effective rule and source without making an LLM request.

## Implementation boundary

`review/internal/config/rules/` owns parsing and resolution. Existing `REVIEW.md`, `AGENTS.md`, instruction files, and `.reviewbuddy.yaml` are migrated deliberately; do not silently ignore them or create competing config systems.

## Release gate

Table-driven precedence and glob tests cover nested paths, unknown extensions, rule merge/replace, invalid config, and escaping. CLI preview and actual review must resolve the same rule.
