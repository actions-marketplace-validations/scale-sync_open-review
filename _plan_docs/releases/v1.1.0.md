# v1.1.0 — controlled codebase context

The commit for this batch uses October 11, 2026 as its Git author and committer date. GitHub shows the actual publication date.

## Added

1. **Read-only context tools:** review rounds can request a selected diff, a regular text file, a bounded file list, or a literal repository search. Local reads use a pinned Git commit; pull request reads use GitHub tree and blob IDs from the reviewed head SHA. Paths, file type, size, search scope, and API responses are checked. Symlinks, binary files, oversized files, and common credential paths are refused. No shell tool is exposed to the model.
2. **Iterative review:** `low`, `medium`, and `high` allow one, three, and five model rounds per group. The model can request one tool per round, record a structured finding, or finish early. Malformed tool requests and findings cannot bypass changed-line validation. The Go CLI uses `--effort`; the PR CLI uses `--effort`; the Action accepts `effort`.
3. **Context compression:** the review task remains intact while older tool rounds become short, labeled summaries when the prompt grows too large. Recent evidence stays in the prompt within the configured per-request token ceiling. Coverage accounting is unchanged.

## Compatibility and limits

The Go JSON contract remains version 2 with an optional `reviewEffort` request field. The trace adds `reviewRounds`, `toolCalls`, and `compressedGroups`. Local workspace context reads use the pinned HEAD tree plus the selected working-tree diff; they do not read mutable worktree files. GitHub context requires a token with repository contents read access. The remote search checks at most 12 eligible files, and local search checks at most 40. Both return at most 10 matching lines.

The release gate covers path escapes, symlinks, binary and large files, pinned revisions, API response bounds, tool limits, cancellation, malformed outputs, prompt-summary fidelity, Go race tests and vet, TypeScript 7 build/typecheck/lint/tests, packaged Action checks, and GitHub CI. On a fixed four-result transcript, prompt composition took about 22 microseconds per operation locally; compression reduced roughly 26 KB of tool evidence to an 8 KB prompt cap. Live model quality and live pull request posting require credentials and a test PR. No package registry publication is included.
