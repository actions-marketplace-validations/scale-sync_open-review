# v1.6.0 — CI delivery and code scanning output

## Added

1. **Mature GitHub delivery.** The Action skips a completed review when the head, selected input, rules, model settings, and engine version match its saved checkpoint. Changed input reruns. Summary posting checks the PR head again; existing sticky summaries and inline markers prevent duplicate comments after retries. The `github-token` input accepts a workflow token or an externally minted GitHub App installation token.
2. **Other CI paths.** GitLab, GitFlic, and Gerrit examples invoke one pinned Go CLI and archive JSON and SARIF. A shared runner preserves partial results and nonzero status. These examples keep hosting credentials outside the review engine.
3. **SARIF 2.1.0.** The Go CLI emits SARIF directly or converts saved JSON without a second model call. Results include relative locations, stable fingerprints, severity, and partial-run status.

## Scope and proof

Local Go and TypeScript suites, the CI runner test, the two YAML adapter contracts, and a Gerrit configuration check pass. A generated finding report validates against the official OASIS SARIF 2.1.0 JSON schema. Live GitLab, GitFlic, Gerrit, GitHub App identity, and code scanning upload were not tested because those platform credentials and destinations are unavailable. No automatic upload workflow is bundled. Package registry publication remains future work.
