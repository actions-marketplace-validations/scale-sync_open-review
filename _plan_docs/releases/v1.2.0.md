# v1.2.0 — explainable rules

The commit for this batch uses October 12, 2026 as its Git author and committer date. GitHub shows the actual publication date.

## Added

1. **Rule precedence:** Go resolves each selected file's effective review guidance in this order: built-in language/config guidance, optional local user `rules.yaml`, repository instruction files and `.reviewbuddy.yaml`, then explicit run instructions. Matching `mode: replace` rules clear lower-priority text; the default is merge. The Go and PR CLIs accept `--instruction`; the Action accepts `instruction`.
2. **Language and path rules:** built-ins cover Go, TypeScript/JavaScript, Python, Rust, Kotlin, and common config formats. Nested instruction files and custom globs apply only to matching paths. Include/exclude flags remain file-selection controls.
3. **Rule diagnostics:** `rules check --file PATH`, `review --preview`, and the JSON request show effective text and source names without an LLM call. Actual review prompts use the same resolved per-file text.

Existing `REVIEW.md`, `AGENTS.md`, `CLAUDE.md`, `.cursorrules`, `.windsurfrules`, and `.reviewbuddy.yaml` feed one Go resolver. The TypeScript GitHub adapter transports their raw contents from the reviewed PR head while preserving the existing chat instruction format. Invalid rule files fail the review instead of silently disappearing. The Go JSON contract stays at version 2 with optional `ruleSources` and `ruleDiagnostics` fields.

Local validation covers precedence, merge/replace, nested and unknown paths, invalid globs/config, symlink rejection, CLI preview parity, actual prompt scoping, Go race tests and vet, TypeScript 7 lint/build/typecheck/tests, and packaged Action checks. Live model quality and live pull request posting still require credentials and a test PR. No package registry publication is included.
