# Local review engine

`cmd/open-review` is the Go command. `gitcmd` resolves local Git inputs, `diff` records each full patch and its metadata, `agent` selects files and checks reviewer output, and `model` defines the versioned JSON request and response. The current JSON shape is recorded in `schema/review-v2.json`.

Use `go run ./cmd/open-review review --workspace` from the repository root. `--repo` selects a different checkout. Choose one mode: `--workspace`, `--base REF --head REF`, `--commit REF`, or `--scan PATH`. Scan reviews a whole file or directory without Git; the path stays inside `--repo`. Add `--deep` for bounded Deno verification, `--output json` for machine-readable output, or `--preview` to show coverage without a model call.

Rules resolve per selected file. Built-in language/config guidance is lowest priority, followed by optional local CLI user rules in `~/.config/open-review/rules.yaml`, repository instruction files and `.reviewbuddy.yaml`, then `--instruction TEXT`. Repository directory instructions apply only below their directory. `.reviewbuddy.yaml` supports `path_instructions` with `path`, `instructions`, and optional `mode: merge|replace`; `replace` clears lower-priority guidance. User `rules.yaml` uses `rules:` with the same fields. The GitHub Action reads repository rules at the PR head and does not read runner user rules. `rules check --file PATH [--output json]` and `review --preview --output json` show the same effective rule text and source chain without an LLM call. Invalid rule files fail the run. Include/exclude patterns select files separately from prompt rules.

For nonempty changes, set the API key for `MAIN_MODEL`: `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, or `GEMINI_API_KEY`. Go calls the model directly and fails with an explicit coverage result when the model returns invalid output. Empty changes need no API key.

Use `config setup` for interactive provider/model selection, `config set --provider NAME --model NAME` for scripts, and `config test` for a small live model request. `--api-key-stdin` stores a key in a mode-0600 user config; `config show` never prints it. `--provider`, `--model`, and `--base-url` override that selection for one review. Custom endpoints require HTTPS, except local HTTP for development.

`--prompt-tokens`, `--output-tokens`, and `--total-tokens` set distinct ceilings. Prompt counts use a rough byte-based estimate before a request; usage totals use provider counts when available and are marked estimated otherwise. A provider can exceed a requested cap; actual usage is recorded and that result becomes partial. `--request-seconds` limits each model request and `--group-seconds` limits the review. A budget stop returns `partial` with any validated findings, and CLI exit code 2; other errors exit 1. `--quiet` suppresses progress, `--output json` prints the stable result contract, and `--output-file PATH` atomically replaces a mode-0600 report only after a result is ready. `completion bash|zsh|fish` prints shell completion.

Files are selected in path order. `--include GLOB` and `--exclude GLOB` are repeatable; a filename glob matches at any depth, `**` spans folders, and a trailing `/` matches a folder. User exclusions win over explicit includes. Explicit includes can override generated, dependency, and supported-file defaults, but never unsafe paths, binary patches, symlinks, or size limits. The default limits are 100 files, 1 MiB per full patch, and 38,000 bytes sent per file; use `--max-files`, `--max-file-bytes`, and `--max-patch-bytes` to adjust them. Patches beyond the send budget are marked `partial`, while the full patch stays in the JSON change record. The model receives only selected content.

Coverage starts as `selected`, `partial`, or `skipped`. On return, selected files become `reviewed`; model errors mark attempted files `failed`. Merge commits compare against their first parent. Untracked files must be regular files of at most 5 MiB each.

Related files in the same folder share a model call when their selected patches fit the 40 KB group limit. Up to three groups run at once under the same token and time budget, with findings returned in group order. Large changes use one short planning call when enough budget remains; its focus cannot change file selection. Failed groups leave the result partial when other groups complete.

`--effort low|medium|high` allows one, three, or five model rounds per group. A round can finish with findings, record one finding, or request one bounded read-only context tool: `read_diff`, `read_file`, `list_files`, or literal `search`. Local file reads use the pinned Git commit rather than mutable worktree files; selected working-tree changes are available through `read_diff`. PR file reads use the reviewed head SHA through GitHub's tree and blob API when `GITHUB_TOKEN` or `GITHUB_PAT` has contents read access. Unsafe paths, symlinks, binary and oversized files are refused. Older tool evidence is summarized when the prompt budget requires it, while the task and recent evidence remain.

Add `--session-dir PATH` to a local review to save a private event trace and reuse completed model groups on the next identical run. The cache fingerprint includes the selected input, rules, effective model, limits, Go runtime, and executable. Workspace reviews save history but never reuse model output because worktree context can change. Session event files are append-only and contain statuses and counts, not prompts, tokens, or provider credentials. Result files contain findings and coverage and should remain private. Use `sessions list|show|inspect|compare|export|delete --dir PATH --repo PATH` to inspect or remove sessions for one repository. Export requires `--output PATH`; delete requires a session ID. A changed fingerprint reruns the model.

Use `sessions serve --dir PATH --repo PATH` to browse saved reviews at a loopback-only address. The page shows events, result coverage, triage, and a before/after finding comparison; each session exports as JSON. The viewer makes no model calls. `sessions triage --dir PATH --repo PATH ID FINDING_ID fixed|ignored|false_positive|open` stores a separate private status file and preserves the original review result. To also resolve or reopen a matching GitHub PR review thread, add `--pr-url URL --thread-id NODE_ID` and set `GITHUB_TOKEN` or `GH_TOKEN`. The command checks the thread's PR, path, line, and title before changing it. A failed GitHub sync leaves local state unchanged.

Deep review runs up to four investigation and sandbox cycles. Deno gets only the selected diff and title through a private temporary script; network, environment, subprocess, and writes are denied. The run records audit events and falls back to an explicitly unverified model pass when Deno is absent. Available linter binaries inspect selected changed files in a checkout matching the reviewed head commit. Only diagnostics on changed lines are included, overlapping model findings are attributed to both sources, and secret matches are never copied into findings. Missing tools are recorded in the audit. Action events disable repository linters by default because their checkout may be untrusted while model keys are present; set `OPEN_REVIEW_TRUSTED_LINTERS=true` only for a trusted workflow checkout.
